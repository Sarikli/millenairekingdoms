# Save compatibility and safe version changes

Millénaire Kingdoms keeps the existing political registry at format6. Capital UUID/native type deterministically supplies personality identity; no personality reroll or duplicate migration field is needed. New paid work lives in separately versioned bounded atomic stores, never inferred from old tax debts or natural projects.

Representative fixtures from the original1.1.0 serializer and retained original1.1.1 binary exercise every saved political/economic field through the current loader, serializer and separate JVM. The1.1.1 generator/provenance is retained in verification/1.2.0/dev.7/: three kingdoms, memberships/revisions, ruler, day42,177 owed deniers, war/peace/truce, one conquest victory/receipt, peace offer, pending join/military mandate and next decision day70. They are representative own-mod SavedData fixtures, not a full old9.0.2 world conversion. Unknown dependency data is not repaired or guessed.

New stores: payment journal1, construction intents3 (strict lazy1/2 migration), shipment/physical operation ledger1, NPC decision history1. Native proof identity1 and nested treasury images2 are retained. Unsupported/future/corrupt stores fail closed without erasing bytes; legacy ambiguous physical operations quarantine. A decision outcome records the initial request, never certifies completed construction/delivery. Refer to individual protocol documents and actual crash matrices.

**A full downgrade from1.2.0 to1.1.1 is not supported.** Unchanged format6 alone does not establish a safe gameplay downgrade:1.1.1 does not track paid construction, held cargo, receipts or new recovery obligations. Back up the whole world before upgrading; restore a matching pre-upgrade whole-world backup to return to1.1.1. Never delete new store files to resolve a pending fee/cargo liability, and never mix snapshots of chunks, native village metadata and transaction files from different times.

If a kingdom/source is captured or destroyed, retirement must precede political publication. Already held cargo remains a visible liability when its original source is no longer authorized; it is not credited to a conqueror or silently deleted. Restoring valid original identity can allow existing recovery; creating a new government does not revive a retired UUID. This conservative case is an explicit limitation, not a successful delivery/refund claim.
