# Millénaire 9.0.3 compatibility audit

Compared `javap -p -s` declarations/descriptors from the unmodified pinned 9.0.2 and 9.0.3 artifacts
for all 34 imported/supporting Millénaire types used by main and GameTest sources.
The original JARs remain ignored; no dependency classes were copied into the addon.

## Existing integration

No public member was removed from those 34 types. Main and GameTest sources compile with 9.0.3.
Kingdom discovery, village types/plans/levels, building inventories, MoneyHelper coin handling,
village records/SavedData, entity/chunk helpers, raids and conquest retain their consumed descriptors.
The VillageSpawnQueue/SpawnVillage and RaidManager/applyLooting/endRaid mixin descriptors are unchanged;
runtime regression is still required to verify injection and behavior, not just compilation.

Notable changes:

- `BuildingInventory.loadChunks(ServerLevel)` is now public. New background services must first check availability
  and postpone rather than use this as a way to force distant inventory chunks to load.
- `Village.markTransientlyLoaded(long)` / `isTransientlyLoaded(long)` and `VillageManager.findVillageInWandRange`
  were added; existing kingdom integration does not need to call them.
- `Millenaire.getContentLoadFailure()` and `MillVillager.isOrdinaryType()` are new; no replacement of old calls is needed.
- Internal growth candidate enumeration changed to `(long, Village, VillageType, boolean, boolean)`.
  This is not an existing addon call, but any royal-construction adapter must inspect the new implementation.
- MockBlock gained a culture-aware replacement overload. Real-capital structure tests remain the behavioral gate.
- Additional items and blocks were registered. No global trade/merchant replacement is introduced.

## New-service investigation boundaries

The real 9.0.3 `ControlledProjectsService` exposes payload/slot/footprint helpers; these declarations alone
do not establish that its player-controlled queue is safe for autonomous royal orders. Inspect actual planning
and builder behavior before selecting an integration point; do not convert NPC villages to controlled villages.
`LocalMerchantHelper` has real transfer/reserve logic and transient loading; its normal behavior must remain untouched.
`MoneyHelper` handles player Inventory denominations. It does not provide a cross-file atomic building-inventory
transaction. New treasury/shipment state requires explicit consistency and recovery design.

## Validation status at the first checkpoint

Build passed after dependency/version metadata updates. The first GameTest launch exposed the test mod's old
hardcoded exact `[1.1.1]` requirement, producing zero tests despite Gradle success. Fixed by expanding the current
`mod_version` when processing test metadata. The runner rejects zero-test launches and stops on startup failures.
The full 9.0.3 runtime/save regression and dedicated-server checks are recorded separately in the progress file.

## Added 9.0.3 read-only construction bridge

`NormalGrowthBridge` consumes the private `getAllCandidates(ServerLevel, Village, VillageType)` overload and
`checkNewBuildingConditions(Village, BuildingPlanSet.LevelDef)`, plus package-private GrowthCandidate accessors
`planSet`, `levelDef`, `variant`, `isUpgrade`. Signatures were inspected in the original artifact. Runtime version must
be exactly 9.0.3; missing/changed methods fail closed. Reflection is isolated/cached here rather than copied engine
rules or a new behavior-changing Mixin. No dependency code is redistributed.

The public catalog uses current engine candidates with normal tier/count/tag/cooldown rules; additionally rejects
upgrades, other cultures, town halls/sub-buildings/parented plans and positive maxCount exhaustion. Its result is a
read-only preview, not proof of resources, placement, payment or construction. The engine chooses a variant when
enumerating; choices need revalidation for a durable order. Existing pending work/ownership is preserved.
Runtime evidence: 6+6 catalog tests, 37 original NPC types/235 choices. Real paid order/building lifecycle is still pending.
