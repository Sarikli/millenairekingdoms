# Observed ocean geography

**Current status:** ocean surveying is fully disabled. The current disabled behavior is documented in [Ocean surveying disabled](1.2.0_OCEAN_DISABLED.md). The implementation/evidence below describes the preserved earlier artifacts; it is not an enabled feature in the disabled build.

This is a separate read-only atlas cache. It changes no village/kingdom ownership, original Millénaire economy, NPC decisions or production world generation. The existing political geometry remains authoritative for its original display purpose. The first RC8 alpha and every validated artifact remain preserved.

## Data and classification

A32×32-block tile contains256 bytes, two bits per **one-block** surface cell: UNKNOWN0, LAND1, OCEAN2, OTHER_WATER3. Missing cells/tiles are unknown, never assumed land or ocean. Rivers/lakes/other surface water remain distinct from sea.

Only actual server-side player positions are sampled, outdoors (`canSeeSky`), within48 horizontal blocks. The sampler uses `getChunkNow` and an already primed WORLD_SURFACE heightmap. It never requests/generates a chunk or primes a heightmap. It reads the actual top block/fluid, surface height relative to sea level, and the already loaded biome at sea level. Pan/zoom/cache/network queries do not sample terrain.

Ocean seeds require real surface water, an ocean biome and a surface within2 blocks of sea level. River biomes and non-sea-level water remain OTHER_WATER. Real vanilla testing exposed submerged beach strips between ocean biomes and the physical shore. Beach water is therefore sea only if a straight, continuous line of **already loaded, sea-level beach water** reaches a real ocean seed within32 blocks along one of four directions. Land, river/lake water, height differences and unknown/unloaded columns stop that direction. No flood fill, seed-based invented shape, historical-cache inference or world scan. Wider/curved/unverified coastal connections remain conservative OTHER_WATER. Supporting columns are not added to the player's map: only the original48-block observation disk is stored.

The transient coastal candidate value4 is never persisted/transmitted; the compact masks remain strictly two-bit. Surface ice/solid cover is observed as land/solid surface, rather than inventing unseen water beneath it.

## Bounds and ownership

Sampling considers at most64 primary columns/player and256 primary columns/20-server-tick interval, with round-robin fairness. A coastal primary column has at most128 additional supporting reads; all are loaded-only and stop at barriers. A10 ms **soft** interval budget is checked between players; an individual acquisition/JIT/OS operation cannot be preempted by this budget. Recreated LRU cursors are staggered so more than16 observers do not repeatedly discover only their first row.

There are at most16 server sessions across dimensions,16384 tiles per player/dimension,128 hot masks/session,64 immutable metadata shards and512 members/shard. An adversarially concentrated shard reaching512 refuses more observations without evicting acknowledged data. Capacity/future/corrupt/missing/contended state is preserved and diagnosed; it is never reset. Failed sessions back off. Cold existing indices are read by one bounded background reader, without capturing a level/server/player or touching chunks; the client receives a retry while loading.

Files live under each dimension's `data/millenairekingdoms/geography/<player UUID>/`. Player/dimension identities are bound into every file. Political public-reveal settings, ruling distant villages, knowing a historical event or another player's loaded chunks do not grant terrain observations.

## Durable format1

A small root index references immutable shard versions; each shard references immutable tile versions. A transaction writes/read-backs/fsyncs new tiles, then new shards, then atomically replaces the root. Only root acknowledgement publishes revisions and permits deletion of revalidated replaced versions. A crash before the root leaves bounded unindexed evidence, never a falsely committed observation. Root, shard and tile fields/types/owner/dimension/UUID/revisions are strict. Hot caches cannot hide future tile/shard bytes before replacement. External root changes and concurrent writer locks refuse updates.

Root reads are bounded to64 KiB accounted NBT, shards512 KiB and tiles4 KiB. Tile/shard orphan allowances and crash-temporary allowances are each64; missing referenced files/unrecognized files are preserved and refused. Native/political/coin/cargo/history files are not part of this cache transaction.

## Read-only protocol8

GEOGRAPHY accepts session/serial plus nonnegative revision-window cursors, reusing the existing bounded from/to wire fields. There are no client coordinates, scan commands, supplied player/dimension identities, foreign kingdom IDs or gameplay actions. Only the current connection's observed cache is returned.

Pages contain at most64 compact masks. Stable watermarks and monotonic per-tile revisions allow observations during paging without retaining server world snapshots. A restored older backup explicitly resets the **client cache only** and downloads its acknowledged observations again. Full pages are validated before client publication. The existing524288-byte overall NBT envelope remains; actual tile responses are far smaller.

## Dev12 bounded live-tick persistence

Live ticks acquire only already loaded surface observations on the server thread, then queue changed own-cache masks to one daemon writer. At most4 write jobs exist globally (one running, at most3 queued), with at most8 masks/job. A pending session is pinned against LRU eviction and exclusively owned by its write future. Main-thread requests return a bounded retry until the atomic root acknowledgement completes; they never race mutable metadata or expose unacknowledged masks. The worker captures no server, level, chunk or player. Shutdown waits up to5 seconds across pending writes and diagnoses unavailable acknowledgements while retaining the last acknowledged cache. Durable format1 and protocol8 are unchanged.

The direct synchronous `capture` entry remains available for controlled correctness/persistence validation; runtime sampling uses `captureAsync`. Its timings include synchronous durable writes and are therefore reported separately from the live sampler. The new fixture deliberately gates only the own-file worker and verifies that live sampling returns, no index is published, queries retry and immediate loaded/forced chunk counts remain equal. After the gate opens it verifies an acknowledged revision and the dedicated writer thread. Its final logged loaded-count is after later fixture ticks and may include natural unloads; the no-load assertion compares the immediate acquisition/query points.
