# 1.2.0 — validation gates

Read [requirements](1.2.0_REQUIREMENTS.md) for all acceptance criteria. No passing claims for unrun tests.

## Phase 1

Build with Java 21 and the pinned 9.0.3 dependency. Audit referenced API/mixin descriptors and metadata.
Run seven sequential suites, each with a fresh world shared only by its write/reload pair:

| Suite | Required tests per JVM |
|---|---:|
| verifyWars | 30 |
| verifyConquest | 25 |
| verifyStage5 | 24 |
| verifyCapitals | 5 |
| verifyAutonomy | 22 |
| verifyGui | 7 |
| verifyFounding | 12 |

Require explicit `All N required tests passed` in both separately launched JVMs. Gradle exit code alone is insufficient.
`scripts/verify-regression.py` records current-run logs/counts under ignored build/verification. Never share worlds between suites.
Run the normal production-JAR dedicated server, verify mod versions and diagnostic commands, save/stop, then restart it.
Keep existing authentic save fixtures and all historical migration assertions; unknown data must not be silently erased.

## New feature gates

- Spending: real denominations/change, value conservation, request replay/concurrency, full/unloaded storage,
  invalid kingdoms/rulers, rollback/refund policy, durable state and tested crash/save boundaries.
- Construction: real legal plans, one order/village, autonomous location/builders/materials, blocked placement/resources,
  normal growth continuing, cancellation, conquest/abdication/destruction, write/reload in every state.
- Shipping: real surplus/reserves, exact escrow content, cost/distance/time, full/unloaded destination, duplicate and
  overlapping requests, ownership changes/destruction/cancellation and independently ordered chunk/SavedData recovery.
- Personalities: every real capital type mapped or justified fallback; restart and capital changes.
- Governance: shared paid services, player-ruler exclusion, reserve/cooldowns, need-based actions, every personality's
  wartime military weight and return to peace, preserved war safeguards, shortage shipments without loops.
- Integration: EN/TR payloads/UI, server authority, save copies, hundreds of simulated days, treasury/blocked-order/shipping
  metrics and CPU cost. Simulated clocks without villager work do not prove real construction completes.

## Release gates

Full regression/new GameTests, real construction/inventories, dedicated server and restarts, conservation/recovery/security
review, representative 1.1.1 save migrations, performance, documented downgrade policy, changelog, RC JAR checksum.
Run graphical tests only with a real graphical environment; list all remaining manual tests explicitly otherwise.
Keep the PR Draft until justified. Do not merge, publish stable releases, or modify stable tags without owner approval.
