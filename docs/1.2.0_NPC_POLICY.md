## Implemented durable attempts and first-fee budgets

RoyalNpcDecisionStore is a separate strict atomic format1, bounded10,000 records/16MiB, under world data
`millenairekingdoms/royal-npc-decisions/decisions.dat`. A complete immutable attempt/selection/capital-type/budget and
next eligible day precede domain issue. Real lock/fsync/atomic rename/directory force are required. Unsupported/future/
unknown/wrong-typed data stays untouched. Same IDs cannot be reused, overlapping cooldowns cannot be admitted, and
result acknowledgements retain original authorization. ISSUING is uncertain caller acknowledgement, not payment or
construction/shipping completion proof. Unissued proposals are never blindly replayed after a crash; actual domain
stores already own recovery of issued IDs. No record pruning or unsupported-format reset is performed.

A narrow shared RoyalPaymentService first-fee hook reads policy provenance for NPC-owned IDs, validates exact original
capital/native type/purpose/reference/fee and bound actual construction village/plan or shipment route/product/quantity/
duration, then rechecks the real physical treasury. Default reserve128 protects two silver coins; maximum fee250 permille
limits one major expense to a quarter. Both current and original frozen settings apply conservatively: the larger
reserve and smaller fee share win. The integer share calculation avoids long multiplication overflow. Owed taxes and
virtual balances never count. A delayed previously-unpaid REQUESTED/PREPARING intent gets this check before its FIRST
financial journal/native delta, not merely at policy selection time. Disabled new economics stops that first fee.

Existing PREPARED/native-proof reconciliation, paid/committed acknowledgements, refunds and legitimate player payments
remain their existing protocols. They do not become a new expense because a reserve changes or new economics is off.
Unknown provenance blocks new NPC first fees rather than guessing that all IDs are untracked; it is never overwritten.
Current authorized player spending is independent. Untracked internal legacy NPC calls retain the existing primitives;
a new automatic coordinator must always persist its own budget attempt before invoking shared domain services.

## Implemented need-based coordinator

RoyalNpcEconomyService inspects a rotating bounded member window (default8, artisan up to16, hard32) without loading
chunks. It requires current active NPC government, a recognized autonomous unowned active loaded capital and real
physical treasury. Player rulers/locally controlled villages/unknown types/resource-cost-disabled games grant no new
policy action. Readonly inspect returns real candidate reasons; evaluate persists cooldown/budget BEFORE invoking one
existing quoted NPC domain service. Changed prices/duration are refused before new intent. A failed domain/result
acknowledgement retains the attempt and original domain evidence, never assumes nothing changed or replays a proposal.

Actual native pending project resource deficits take priority. Full native required maps and original anywood/fixed-log
overlap semantics are read behind loaded chest/furnace/firepit guards. Eligible member sources contribute only current
ordinary protected surplus; maximum64 goods/2048 horizontal blocks, normal real distance/quantity fee and duration.
One active shipment per kingdom, persistent bidirectional pair cooldown6 days (artisan3), and current deficits avoid
repeated/unnecessary shipments. Artisan capitals inspect more candidates and revisit routes sooner while obeying all
shared safeguards. Existing native projects can be supported without a royal construction order. A saved native-pending
fingerprint is diagnostic need provenance, never proof of queue ownership; no project is removed/replaced. Already-issued
logistics retain their original authorized route as the world changes; new decisions require a fresh actual shortage.

New commissions require no existing tracked major project, an idle native pending/task opportunity, current original
legal same-culture catalog choices, full actual native materials and a loaded living available original builder whose
type has the real build goal (not child/hired/raiding/NoAI). Only classified missing functional coverage is considered.
Peacetime aims at one food/faith/production/defense function; war military need scales with real living population up to4
facilities. Existing native buildings count, townhall is separate. Civic investment is limited to developed capital
level2+, at least3 members, missing civic coverage and treasury at least4 reserves. Lower-development gaps get greater
relative weight. RNG selects only among independently justified eligible choices; money alone is not a need.

Default persistent cadence:3 days between ALL attempts,6 days between kingdom commission attempts,12 days in the same
village. Failed/non-action attempts retain cooldown. Settings must keep projectDays>=attemptDays and villageDays>=
projectDays; invalid combinations refuse new decisions rather than silently weaken them. Existing paid/domain recovery
continues independently. This stage adds configuration only for gameplay, not cloud environment setup/start instructions.
