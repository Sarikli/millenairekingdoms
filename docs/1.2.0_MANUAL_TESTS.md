# Unverified client checks / Doğrulanmamış istemci kontrolleri

These are **not passing results**. The cloud session has no DISPLAY/Wayland/Xvfb and no established authenticated
Minecraft session. Automated server/data/codec results are documented separately in the progress/test plan.
Use matching client/server development builds and a copied test world; no new cloud setup is prescribed here.

- [ ] Open the existing kingdom screen in English and Turkish; verify all seven tabs, existing actions, tooltips and translations.
- [ ] Check default/small window and GUI scales, long native plan/village names, list scrolling and full-name hover text.
- [ ] Check village switching, native plan selection, displayed real price, disabled reasons and current village availability.
- [ ] Order a genuine autonomous village building; observe NPC site selection/material fetching, work percentage and final status.
- [ ] Refresh and double-click/repeat requests; check one actual fee, a stable saved order and a usable new offer after unpaid cancellation.
- [ ] Let an offer expire/change its server price; verify the refreshed price is reviewed before a new payment.
- [ ] Check resumed partial requests, cancellation confirmation/refund wording, retained accepted fee and continuing village work.
- [ ] Verify unloaded/missing materials/site/builder/recovery and unreadable-data messages fit without covering controls.
- [ ] In Shipping / Sevkiyat choose source, destination, product and quantity; apply quantity and inspect physical stock, safe surplus, fee and estimated time.
- [ ] Verify changing source can select the previous destination, including a kingdom with only two villages; source and destination must remain distinct.
- [ ] Check shipping quantity entry, long product names, status/history cycling, actual delivered/held/returned quantities, retry and two-click cancellation.
- [ ] Read pre-dispatch refund and post-dispatch earned-fee tooltips; verify full/unloaded destinations remain waiting without losing held goods.
- [ ] Check expired/changed shipping offers, changed local ownership, ruler retirement and repeated existing IDs against actual inventories and capital coins.
- [ ] Connect with a legitimate authenticated account to an online-mode dedicated server; confirm actual authenticated login.
- [ ] Confirm mismatched protocol-1/2 or old-mod clients are refused cleanly, and matching protocol-3 clients can use the screen.
