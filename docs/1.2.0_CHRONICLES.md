# Authoritative chronicles

Baseline RC.8 remains preserved; this extension uses separate `data/millenairekingdoms/history` in each dimension. Political format6, payment1, construction5, recovery2 and shipment1 are unchanged.

Facts are immutable version1 events, identified by dimension + event kind + original operation identity. Historical kingdom/village names, culture, ethos, locations and known actors are captured separately from presentation. No assumed religious insult, diplomatic incident, ruler identity or old founding date is introduced. New kingdoms begin with a real founding event; old kingdoms start with unknown past and newly observed transitions.

Immutable individual event files form the commit boundary. Startup builds bounded secondary indices once (100,000 events/dimension); page reads use date/kingdom/type indices and load only selected24 records. Retries compare exact facts. Unknown formats/fields/invalid types preserve bytes. A full archive refuses new appends and reports the problem, never prunes old records.

Political hooks run after economic governance guards and stage a separate pending batch before publication. Events become queryable only after the existing political serializer/worker and actual disk read-back match the projected new political state. Unconfirmed pre-publication batches stay pending and do not invent history. Reload can finish a confirmed batch idempotently. History I/O errors are separate diagnostics: no political, money, cargo or NPC transition is replayed to repair history.

Construction acceptance requires actual durable native publication and committed fee. Actual completion is separately recorded after the original physical/native persistence proof and terminal order acknowledgement. Newly enrolled mandates are distinguished from pre-existing accepted RC.8 orders, avoiding backfill on retry. Significant autonomous commissions also produce an investment event. Delivered shipments are significant at quantity>=64 or transport fee>=8; cancelled/merely collected cargo does not count as delivery. Routine taxes do not produce history.

Domain events have their own durable pending event before archive append; recovery retains their original event time and names. Arbitrary cross-file power-loss atomicity is not promised. An interruption before the observer stages its own pending data remains a hardening case, explicitly tracked in alpha progress.

## dev7 causal commit hardening

Current political maximum schema is7: the only addition is an optional causal UUID for a real live transition; legacy1–6 remain supported and a read-only6 world stays6 until needed. Political candidate format2 uses that exact UUID after actual serializer/worker/disk evidence, then durably marks confirmation before archive append. Equal later snapshots cannot authenticate an earlier failed transition. Composite player founding is validated detached before its single publication; a failed ruler check cannot create intermediate historical success. Domain candidate1 binds the exact existing full order/shipment intent before final acknowledgement and requires accepted/completed/delivered stage plus its original committed fee. Native physical completion and actual cargo proof remain existing services. Confirmed backlog and original times/names survive append failure; bounded read-only recovery never replays domain actions. Legacy unconfirmed alpha pending1 is retained for review; native/political6-without-marker/payment1/order5/recovery2/shipment1 mechanisms are protected. Final crash/runtime/regression evidence is still required; see alpha progress.
