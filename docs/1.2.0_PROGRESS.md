## Order service implementation notes

The store is not registered as SavedData; it atomically rewrites its own bounded index with filesystem locking, file and
parent-directory sync. Terminal tombstones are retained. RECOVERY_REQUIRED retains the village reservation; it never
automatically resets. Do not mark metadata PAID/QUEUED merely because a caller asked: the service must obtain actual
payment and SavedData read-back evidence first. Original building IDs forbid fulfilling a new order with an old building.
Future order services need strict same-ID/cancellation recovery across order/payment/Millenaire files. A new request with
an existing order ID must load its stored variant/price before recomputing a random catalog preview or current config.
A dynasty/ruler timestamp alone cannot detect same-tick abdicate/reclaim; the tested pre-publication retirement hook now closes this gap. Offline player orders must not be resumed through the NPC spending path.
Once a queue acceptance is durable, patronage is committed/nonrefundable; post-start cancellation must not demolish or
freeze an autonomous NPC building. Pre-acceptance cancellation persists its decision, then refunds the original payment.
Internal paid queue insertion is now implemented/tested. No GUI/NPC scheduler consumer exists yet. Actual representative builder/completion proof now exists (48+48).
