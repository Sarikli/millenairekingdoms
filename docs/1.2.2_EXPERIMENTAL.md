# 1.2.2 autonomous economy experiment

Current candidate under verification:1.2.2-dev.3. Development branch feature/1.2.2-autonomous-economy, Draft PR5. Stable1.2.1 and main remain unchanged. The frozen dev2 natural120-day run completed/reopened but produced0 actual economic orders; its economy-liveness acceptance failed.

- Persistent unpaid building plans wait behind native work.
- Planned projects can request genuine partial supply shipments.
- Building and supply orders use independent IDs and existing physical payment/cargo protocols.
- Bounded temporary economic leases activate previously generated villages without nearby players.
- Assigned NPC builders retain construction cargo until their project finishes.

Fresh-world policy uses64 retained deniers and a50% maximum first fee. Earlier/custom server TOML values remain effective; previously frozen stricter approvals also remain protected. The readonly OP2 command `kingdoms economy explain <kingdom>` reports actual settings, both lanes, physical availability and background work diagnostics.

One server-wide lease uses at most1024 temporary chunk tickets,4 new status scans/ticket requests per tick and16 outstanding disk jobs across lease changes. Large original Norman work regions can occupy272 chunks, so the former384 limit could not accommodate ordinary multi-village logistics. Only an additional speculative supply village that fits the same limit is included. Active shipments already specify their source. Requests from other kingdoms wait in a bounded FIFO, avoiding first-sorted-kingdom monopolies. Military operations take priority. Missing terrain, unknown authority and over-budget regions remain explicitly deferred; no new terrain, coins, cargo, NPCs or completion are invented.

In a dimension with no players or persistent forced chunks, Minecraft stops the ordinary entity loop after300 ticks even when transient tickets load work regions. Dev3 renews the public empty-level grace timer only during a valid WORKING lease. Native entities and block entities then use Minecraft's normal tick path; ticket preflight, military priority, lease expiry and absence of permanent force flags remain unchanged. Verification now removes the GameTest harness's persistent force flags so it exercises the real empty-dimension condition.

The original9.0.3 shop-delivery goal scores ten points per carried item:163 construction logs score1630, above native construction's1500. Real native tests reproduced the builder moving these goods to shops during unfinished construction. The addon uses the public native goal-registry extension to defer this shop goal while a current NPC-kingdom builder carries assigned project resources. Native building steps, material fetching, actual consumption, combat and other goal rules remain original. Custom third-party delivery replacements are retained.

The focused package evidence and remaining long observation are recorded in [progress](1.2.2_PROGRESS.md) and [test plan](1.2.2_TEST_PLAN.md).
