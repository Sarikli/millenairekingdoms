Native pending/tasks are never replaced; wall slots stay independent. The original online mandate, current native eligibility, loaded target/treasury and real funds are checked before the existing durable payment path. Cancellation/authority retirement require no receipt, preventing an unpaid refund. Format4 strictly reads1–3 and retains cancellation/recovery provenance. Atomic first-publication baseline union excludes native work created while waiting; the financial tuple never changes, and published/uncertain work cannot rebase.

The genuine native upgrade exposed a20-tick native/100-tick recovery-poll race. The new require1 pinned HEAD injection does not cancel/replace native growth; a per-village cached WAITING entry gets one busy→ready attempt, with the original method always continuing. No entry means no file I/O or global village scan. Periodic recovery retains its normal budget; simultaneous native handoffs can add synchronous persistence work, so historical simulation timings are not a new RC.7 stress guarantee. EN/TR add6 matching keys each (320 total); Ethos/Karakter, RC.5 timings, stock protections and other domain serializers remain retained. Earlier review sections below record the original RC.1 evidence.

Review applies to the1.2.0 development branch, not an independently certified security audit. Final regression status is recorded in the progress and release report after actual completion.

## Authority and gameplay boundaries

- C2S action/text codecs are bounded32/128 characters; connected ServerPlayer supplies actor and dimension. Shared4-tick action throttle and current server authority/reputation checks apply. Server-owned expiring full-bound offers never trust client fee/capital/tenure/plan/route. Existing durable UUIDs keep immutable terms and reject another ruler/tenure. Construction14, shipping17 and existing GUI7 per-JVM gates exercise these boundaries; graphical rendering/authentication is separate.
- New production services do not call world block placement, entity spawning or chunk forcing. Construction enters only the original legal pending API; its original site/builder/material engine remains authoritative. Native wall segments use the engine's independent slots. Paid tracking reads tasks/blocks/material/entity persistence and never advances a task or synthesizes completion.
- KingdomSavedData retains atomic political transitions and format6. Existing political guards are kept; personality modifies eligible probabilities only. Prepublication retirement can conservatively cancel work if a later publication fails; it cannot retain an obsolete spending mandate. Player government excludes new NPC policy.
- No mandatory market, global instant stockpile, caravan requirement, trade interception or ownership conversion was added. Native inventories remain real and independent.

## Currency, cargo and recovery

Actual denominations4096/64/1, protected custom coins, physical authority/identity and immutable full intents govern every new debit. Owed taxes are not spendable coins. Native Items and bound operation proofs are acknowledged/read back before journal acknowledgement, so later legitimate inventory activity is preserved. Unproven or legacy ambiguous physical evidence quarantines rather than guesses paid/unpaid. Shared money/cargo/withdrawal reservations prevent overlapping unacknowledged native images.

Goods reserve full original pending/being-built/controlled tasks, native targets/household needs and configured minimum stock. Original anywood/fixed-log semantics prevent counting one timber twice. Cargo is actual APPLIED collections minus deliveries/returns, with full native proof images and original endpoint identities. Predispatch returns precede fee refund; dispatched transport keeps its fee. Captured original storage leaves explicit held liabilities, no conqueror redirect. The confirmed new-return authority exception now persists the same MEMBERSHIP deferral as existing prepared returns.

Seven actual receipt cuts, eight construction publication/cancellation cuts, genuine physical completion crash/damaged-save guards, ten cargo cuts and three joint fee/domain cuts are preserved in earlier verification directories. Expected halt70 runs are failures intentionally placed between successful prepare/recover JVMs; they are never counted as passing tests. These establish tested process-crash boundaries, not arbitrary hardware power-loss atomicity across a whole Minecraft world.

Versioned atomic stores use strict fields, size/count bounds, locks, fsync and atomic rename. Future/corrupt data is preserved and blocks uncertain new actions. Existing paid recovery does not depend on later reduced NPC budgets. Retired initial decisions never reissue blindly. OP2 audited recovery records actor/reason/evidence before resolving existing construction and cannot fabricate resources or revive retired mandates.

## Bounded runtime and cost

Construction/shipping tracking defaults100ticks/2jobs, NPC decisions1200ticks/2kingdoms, persistent3/6/12-day attempt/project/village limits. Rotating member window8 (artisan16, hard32), cargo64, route2048; no full-world chunk scans. Independent automatic domain trackers prevent new untracked paid jobs. Unknown/config-invalid NPC startup pauses spending and preserves history. Runtime session/error maps clear on stop; diagnostic logging is bounded.

The400-day/four-JVM scenario measured1252 decisions/10 realms with actual strict disk work: warmed per-evaluate p95 about15–24ms, bounded default runtime p95 about41–82ms, cold maximum297ms. Occasional synchronous tick delay remains measurable; this is not a20TPS/huge-world stress guarantee. Stores are capped (NPC history10000/16MiB); automatic new decisions stop conservatively if capacity is exhausted instead of discarding financial provenance. Existing domain recovery and ordinary Millénaire remain separate. No speculative cache weakens current-coin/history validation.
