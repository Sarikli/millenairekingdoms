# Audited royal construction recovery / Kayıtlı inşaat kurtarma

Latest verified follow-up: [RC.8 upgrades/product picker/capital production](1.2.0_RC8_UPGRADES_AND_INCOME.md). Player upgrades bind an existing non-centre building UUID and next native level; the original pre-upgrade complete building cannot fulfill them. Price scales linearly by target display level, with real materials/builders retained. Network4/order5 (lazy1–4)/audit2 (lazy1); political6/payment1/shipment1 remain unchanged. Capital4-per-completed-level daily production uses the existing ledger. Earlier milestone sections below are historical.

This is an operator maintenance facility, not a new commission or a financial-journal reset.
Use permission level 2 in the order's original dimension. Review the original village, plan, receipt and building first.
Only an exact already durable `PAID`/`COMMITTED` CONSTRUCTION receipt with the original actor, capital, amount and order
reference is eligible. PREPARED, third physical images, missing/conflicting receipts and already refunded money are
never converted into paid patronage by these commands. Copy the world before manual investigation of those cases.

## Commands

All commands start with `/kingdoms royal_recovery`:

| Command | Effect |
|---|---|
| `inspect_order <order UUID>` | Display immutable plan/fee/village, stage, reason, bound building and last recovery decision. |
| `list` | Display retained decision IDs, operators, reasons, evidence, states and execution results in this dimension. |
| `adopt_pending <order UUID> <reason>` | Review and adopt an existing exact original pending project. No new pending work is created. |
| `adopt_building <order UUID> <building UUID> <reason>` | Bind the unique genuine new matching original building/task outside the order's original building snapshot. |
| `forfeit_fee <order UUID> <reason>` | Explicitly retain already paid patronage and stop tracking. No refund, redirection, queue removal or demolition. |
| `resume <decision UUID>` | Resume the same persisted review after a failed acknowledgement. |
| `abandon <decision UUID> <reason>` | Record withdrawal of an unapplied review, retaining the quarantined order and money. |

A nonblank printable reason of at most 256 characters is mandatory. The command prints its new decision UUID. On a
failure, inspect the list and resume that UUID: durable changes may already exist. Never keep issuing fresh decisions
to conceal a failed acknowledgement. One AUTHORIZED decision reserves each order until DONE or explicitly ABANDONED.
Abandon cannot undo an applied decision; resume closes its retained audit instead. Terminal audit history is immutable.

Adoption requires the same valid original mandate, member village/type, autonomous control, ruler tenure/reputation and
normal material costs. A cancelled or authority-retired mandate cannot be revived, even if authority returns in the
same tick. Pending evidence must be exact and have no competing new matching building. Building evidence must retain
the original lineage, genuine nonempty native task (or valid later upgrade), uniqueness and any existing UUID binding.
Original save/read-back precedes adoption; completed structures also pass the physical completion barrier. Unloaded
building chunks defer without forcing them. Original builders retain complete responsibility for placement/materials.

## Persistence and replay

`data/millenairekingdoms/royal-recovery/decisions.dat` is a separate strict format-2 bounded atomic audit (lazy format1 reads). It retains
the full original order intent, unique decision ID, mode, optional genuine building UUID, operator UUID/source, reason,
issue time and final executor/reason/time. Unknown/future/corrupt data and lock failures preserve the original file and
prevent resolution. History is capped at 1000 decisions pending a future explicitly reviewed archival facility.

The review is durable **before** acknowledging an existing paid receipt or resolving the order. Original engine evidence
is rechecked/acknowledged at execution. Receipt acknowledgement performs no new debit/refund or inventory operation.
Order format **5** retains the format3 recovery provenance and writes the resolution and `recoveryDecision` provenance atomically. This field is necessary: if audit
DONE fails after the order write, later progress/retirement must not erase proof that the decision already applied.
Replay then only acknowledges DONE; it cannot reopen the retired order, charge again or infer success from a plan name.
Strict v1/v2 reads are lazy and preserve bytes; their first successful mutation writes v3, retaining cancellation origins,
full intents, building IDs and terminal tombstones. Political format 6 and payment format 1 remain unchanged.

The bounded existing-order runtime can resume only reviews already authorized by an OP. It cannot invent a review.
Review and ordinary tracking share the same UUID round-robin and **total** configured per-step budget; review replaces
its order's ordinary job. Disabling construction tracking pauses automatic resume but leaves manual OP resume available.
No speculative financial repair, alternate treasury refund or global per-tick inventory/terrain scan is introduced.

## Türkçe kullanım

Bu komutlar yalnızca OP yetkisiyle, siparişin özgün boyutunda kullanılır. Önce `inspect_order` ile siparişi ve dünyadaki
gerçek işi inceleyin. `adopt_pending` mevcut özgün bekleyen işe, `adopt_building` özgün motorun oluşturduğu tek geçerli
binaya bağlanır. İkisi de yeni iş, bina, eşya veya NPC üretmez. Yetkisi sona ermiş sipariş yeniden başlatılamaz.

`forfeit_fee`, önceden gerçekten ödenmiş ücreti iade etmeden kraliyet takibini kapatır; köyün bağımsız işi sürer. Her
karar için açıklayıcı bir gerekçe gerekir. Komutun verdiği karar kimliğini saklayın. Hata olursa `list` ile kaydı inceleyip
aynı kimlikle `resume` kullanın; işlem kısmen kalıcılaşmış olabilir. Henüz uygulanmamış karardan vazgeçmek için `abandon`
kullanılır; bu işlem para iadesi veya sipariş iptali değildir. Belirsiz fiziksel ödeme kayıtları bu araçla sıfırlanamaz.
