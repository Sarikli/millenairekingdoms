# Independent political atlas

The atlas is a read-only political visualization, with no mapping-mod dependency, land claim, native village-boundary, AI, goal, economy or local-owner mutation.

## Geometry and colors

Each actual visible registered settlement contributes a48-sided influence polygon (default500-block radius), clipped by nearest-settlement bisectors of overlapping neighbors. Spatial buckets bound neighbor searches; same-kingdom internal borders are suppressed. Distant disconnected settlements keep separate regions, with no corridor drawn across uninfluenced land. Coincident coordinates use a stable UUID tie, preserving both markers but assigning one finite visual region. Persistent kingdom UUIDs deterministically produce colors; neutral villages have a separate neutral color. Geometry cache keys include dimension, radius, identities, coordinates and current allegiance. It is rebuilt on relevant snapshot changes, reused for pan/zoom. Limits8192 sites and512 overlapping neighbors prevent unbounded geometry work; this is not a huge-world/TPS guarantee.

## Server-controlled visibility

Only current-dimension registered metadata is read; there is no terrain/chunk scan or forced loading. Default discovery requires an already loaded settlement within512 horizontal blocks of the player. Current ruler members and locally owned villages are also known. Learned village identities persist in a separate strict version1 per-player/per-dimension store (limit16384). Past knowledge remains after moving away or political ownership changes. Unknown/future discovery bytes are preserved and refused.

Gameplay configuration `politicalAtlas.influenceRadiusBlocks=500` (64..4096), `discoveryRadiusBlocks=512` (64..4096), `revealAllRegisteredSettlements=false`. Public reveal is an explicit operator opt-in; coordinates already revealed cannot be made unknown by switching it off. These are new display/visibility keys; existing gameplay settings remain intact. Cloud setup/start/environment files are untouched.

History responses redact unknown locations before network encoding and remove foreign treasury amounts. Historical sites may later be located using remembered IDs, even if they no longer have a current settlement marker. Current borders must always be labeled current ownership, with historical event pins distinguished by date. Animated historical border playback is outside scope.

## Interactive view

The full-screen renderer implements zoom/pan/hover/selection/list/legend/info, actual original village-type item icons and bounded authoritative128-site snapshots with current membership/war/economic privacy. Geometry runs asynchronously off the renderer/server simulation thread. Direct event/kingdom/village links and dated historical pins connect the chronicle and atlas. Geometry/server tests do not establish visual correctness or actual client input. Real graphical positioning, mouse interaction, scales, label fit and authenticated login remain manual/unverified here.

## Synchronization and history links

24-entry history queries support village indices and participant perspectives. Direct event/place/kingdom links open the standalone atlas; hidden coordinates remain absent. The map's historical pin is dated and separate from current settlement coordinates/ownership. Client pages are assembled for exactly one revision, with consistent radius/dimension/count/cursor and unique bounded village IDs; only a full defensive frame becomes renderable. A revision change restarts assembly, preserving the earlier complete frame while loading. Automatic checks every100 client ticks while open send only a first page when the whole snapshot revision is unchanged. Pan/zoom reuse mesh; capital lookup and viewport culling avoid redundant work. Explicit correlated retry replies handle server request throttling. These are source/server/model behaviors; actual graphical navigation/input/scales remain manually unverified.


## Authoritative information and passive treasury reads

Selected kingdom information includes current capital/culture/ethos, known or explicitly unknown founding day, membership count and visible village types, current war/opponent, NPC/player government and chronicle link. Member pages128 rows preserve expanded lists and pane scroll on unchanged refresh. Current ruler alone receives income/owed/physical treasury; other viewers receive no economic fields. Local village ownership and political rule remain separate.

The atlas checks every declared storage position and any connected double-chest half is already loaded before invoking the existing native coin scan. An unknown half defers the amount rather than loading its chunk. A corrected real chunk-edge test reproduced the prior observer bug and now verifies no forced load plus the true nine-coin amount once both halves are explicitly loaded. This guard changes only the new atlas read path, not TreasuryService, native containers or stock/financial policy.

## Controls and manual review

Open **K → History/Tarihçe → Political Atlas/Siyasi Atlas**. The atlas occupies its own screen. Scroll over the map to zoom around the cursor; drag empty map space to pan. Click a marker/territory or a kingdom in the list to select it. Gold-framed native type icons indicate current capitals. The panel can be hidden; switch between kingdom list and information. Member rows locate villages; the history action opens the selected village/kingdom chronicle. Back/Esc returns to the actual parent. A dated yellow historical pin is distinct from present borders.

These controls are implemented and compiled, but no graphical client was available.
