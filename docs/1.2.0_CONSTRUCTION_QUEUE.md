# RC.7 — royal construction waiting queue

A player can review a currently eligible native plan and queue one royal mandate behind a village's existing ordinary construction or upgrade. The current native pending project/task is preserved. Native wall work uses its independent slot. This change does not add new NPC investment decisions or a general multiple-building queue.

## Player behavior

Open **Rulership → Construction**, select the village/plan and choose **Queue** while native work is pending. The saved **WAITING** order reserves that village's one royal slot, retains the reviewed fee/variant and takes **no coins**. It can be cancelled without a debit/refund or cancelling the village's job. Refresh shows the current obstacle; Resume retries the same UUID.

After the original job finishes, the existing bounded construction scheduler automatically retries the order. The original ruler must be online in the same dimension, still hold the same mandate/reputation and retain the same capital/member village. The target and original treasury must actually be available; production never forces chunks. The server rechecks current native eligibility/count/cooldown and real funds, then uses the existing durable debit/publication path. Automatic handoff follows the existing construction-tracking enable switch; disabling tracking pauses automatic work without erasing the mandate. The default recovery poll remains100 ticks/2 jobs, at HIGH event priority. Native growth has a per-village20-tick counter, so a poll alone can miss the newly empty slot. A narrowly pinned pre-growth hook checks only that village's cached persisted WAITING mandate. It attempts once at the busy→ready boundary before native selection, using all the same service/payment checks; the original native call always continues. No waiting entry means no store I/O or village scan in the hook. Offline actors cause no debit; a failed acceptance lets native growth continue. Startup/periodic reads refresh the cache, and stopping discards it. There is no global every-tick scan or replacement of native work.

Insufficient money, unavailable storage or a newly ineligible plan leaves the order unpaid and visible. The waiting mandate is not a guarantee that a plan will remain eligible after the first job completes. Cancel/reselect if its native limit or conditions changed. Patronage pays for acceptance, not materials or instant completion; the original village still chooses a legal site and real NPCs use actual materials. Durable accepted patronage is retained under the existing cancellation policy. A later uncertain publication remains quarantined for explicit recovery.

The original ruler must return after restarting the server; this is not offline impersonation or an offline spending path. Governance retirement permanently cancels an unpaid waiting mandate; reclaiming rule does not revive it. One active royal mandate per village includes WAITING and uncertain recovery states. Current shipping reserves, taxation, political thresholds/timers, Ethos/Karakter and the other pages remain unchanged.

## Storage boundary

Construction intents advance **format3 → format4** for WAITING and its diagnostic states. Strict formats1–3 load without eager file writes; a successful locked mutation writes4 while retaining prior financial/cancellation/building/recovery/terminal identities. WAITING requires a player actor and no adopted building; an unexpected payment receipt is quarantined rather than treated as unpaid. Unknown/future/malformed data remains preserved and unavailable. Political6, payments1, recovery-audit1 and shipment1 stay unchanged. Back up the whole world before upgrading; RC.6 and earlier cannot read format4. Restore a matching whole-world backup to downgrade; do not delete transaction files.

A natural building may be created while the order waits. Immediately before its **first** engine publication, PAID→QUEUING atomically extends the observation baseline with all then-current native building UUIDs. Thus a preceding natural building with the same plan cannot fulfill the royal order. The financial request/quote tuple is unchanged. Already published or uncertain orders cannot rebase their evidence; original acknowledgement/quarantine rules still apply.

## Türkçe

**Hükümdarlık → İnşaat** içinde köyün mevcut işi sürerken uygun planı **Sıraya al** ile kaydedin. Köy başına tek kraliyet emri vardır. **Bekliyor** aşamasında ücret alınmaz; iptal, köyün kendi işini etkilemez. Mevcut inşaat/yükseltme bitince aynı hükümdar aynı boyutta çevrimiçiyken, köy/hazine yüklenmişse ve plan hâlâ uygunsa emir otomatik kabul edilir; kayıtlı bedel bir kez ödenir. Para, depo veya uygunluk eksikse ücretsiz bekler ve gerekçesi görünür. Yeniden açmada kayıt korunur; hükümdarın geri dönmesi gerekir. Kabul sonrası malzeme ve gerçek inşaatçı gereksinimleri devam eder.

İnşaat kayıt biçimi4 olur; eski1–3 kayıtları koruyarak okur. Önceki sürüme dönüş için eşleşen tam dünya yedeğini kullanın. Diğer kayıt biçimleri ve sevkiyat stok koruması değişmez. [Gerçek test sonuçları ve sınırlar](../verification/1.2.0/rc.7-construction-queue/README.md).
