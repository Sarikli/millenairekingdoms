# Millénaire Kingdoms 1.2.3 — Minecraft 26.3 port

Unofficial port of [Millénaire Kingdoms](https://github.com/Sarikli/millenairekingdoms) **1.2.3** (Minecraft 1.21.1 / NeoForge 21.1)
to **Minecraft 26.3 / NeoForge 26.3.0.100 / Millénaire 9.1.0+mc26.3**. Branch `mc26.3`, based on tag `1.2.3`.

## What changed
- Code moved to the 26.3 APIs: `ResourceLocation` → `Identifier`, `GuiGraphics` → `GuiGraphicsExtractor`, NBT reads with
  `getIntOr` / `getStringOr` / `getCompoundOrEmpty`… (including reads that compiled but returned an `Optional`), chunk positions,
  permissions (`Permissions.COMMANDS_GAMEMASTER`), world clock, chat events, world heights, data version.
- Millénaire version checks accept `9.x` instead of exactly `"9.1.0"` (the 26.3 build reports `9.1.0+mc26.3`).
- `@ApiStatus.Internal` (not available in 26.3) commented out; JetBrains annotations → JSpecify.
- Data folder paths and directory fsync fixed for Windows.
- **Added cultures**: `compat/ExtraCultureMappings.java` classifies the village types and buildings of extra Millénaire cultures
  (generated by `tools/mc26.3/gen_extra_mappings.py` from an installed `millenaire-custom` folder), so that kingdoms whose capital
  belongs to an added culture get a personality, NPC strategy and royal investment. The original tables keep priority.
  Chronicle traditions for these cultures were added (English and French).
- `pack.mcmeta` uses the 26.3 resource pack format (97).

## Build
- **Tested way** (how this jar was built and played):
  `python3 tools/mc26.3/build.py <dir with the Minecraft 26.3 / NeoForge 26.3 jars> <millenaire-9.1.0+mc26.3.jar> [javac 25]`
  → `build/millenairekingdoms-1.2.3+mc26.3.jar`.
- **Gradle**: `gradle.properties`, Java 25 toolchain and the mods.toml template are set for 26.3, but the ModDevGradle plugin
  version for 26.3 was **not tested**. Put `millenaire-9.1.0+mc26.3.jar` in the project folder (its SHA-256 is in
  `gradle.properties`).
- The GameTests (`src/gametest`) were **not ported** to 26.3.
